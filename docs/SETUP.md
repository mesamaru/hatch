# セットアップ手順

Hatch の導入は「Proxmox でコマンドを1回実行 → ブラウザで初期設定画面に入力」の2段階です。
コンテナの中でコマンドを打つ必要は、基本的にありません。

各キーの取り方は初期設定画面にも表示されます。このページは、事前に値を集めておきたいときや、画面が開けないときのためのものです。

---

## 全体の流れ

| 順番 | どこで | やること | 時間の目安 |
|---|---|---|---|
| 1 | Proxmox ホストのシェル | インストールのコマンドを実行 | 5分 |
| 2 | ブラウザ | 表示された URL を開き、初期設定コードを入力 | 1分 |
| 3 | ブラウザ | 初期設定画面の案内に沿って、各サービスのキーを入力 | 20〜30分 |
| 4 | ブラウザ | Discord でログイン → 管理画面でドメインとアドレス枠を登録 | 10分 |

### 1. インストール（Proxmox ホスト）

```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/mesamaru/hatch/main/ct/hatch.sh)"
```

最後に次のように表示されます。

```
Hatch の準備ができました。 続きはブラウザで行います。

   1. パネルを開く      http://192.168.1.50:8080
   2. 初期設定コード    K7QM-3RXA-WP9D
   3. 画面の案内に沿って、ゲームパネル・Cloudflare・Uptime Kuma・Discord を設定
```

### 2. 初期設定画面を開く

表示された URL をブラウザで開くと、初期設定画面になります。初期設定コードを入力してください。

コードを見失ったときは、Proxmox ホストで `pct enter <コンテナID>` を実行し、コンテナの中で `hatch-setup` を実行すると再表示されます。

> 初期設定コードは、パネルを先に開いた第三者に設定を乗っ取られないためのものです。初期設定が終わると使えなくなります。

### 3. 初期設定画面で入力する項目

画面は次の順に進みます。各ステップの **接続確認** で、入力した値が正しいかその場で確かめられます。

1. 初期設定コード
2. このパネルの URL
3. ゲームパネル（Pterodactyl）
4. Cloudflare
5. Uptime Kuma
6. Discord のアプリと Bot
7. Discord のロールとチャンネル（一覧から選ぶだけ）
8. 確認して保存 → 自動で再起動（10秒ほど）

保存すると Hatch が自動で再起動し、Discord でログインできるようになります。

---

## 各キーの取り方

### このパネルの URL

| 項目 | 入れる値 |
|---|---|
| 公開 URL | 利用者がブラウザで開く URL（例 `https://hatch.example.com`）。Discord ログインの戻り先になります。まだ公開していなければ、今開いている URL のままで構いません |
| Tailscale 内の URL | `http://<Tailscale のマシン名>:8080`（例 `http://hatch:8080`）。Uptime Kuma からの通知の送り先です。マシン名は Tailscale 管理画面の Machines で確認できます |

### ゲームパネル（Pterodactyl）

キーは作成直後に一度しか表示されません。作ったらすぐにコピーしてください。

**Application API キー（`ptla_` で始まる）**

1. Pterodactyl に **管理者** でログインし、右上の歯車（管理画面）を開く
2. 左のメニューの **Application API** → **Create New**
3. Description に `hatch` と入れ、すべての項目を **Read & Write** にする
4. **Create Credentials** → 表示されたキーをコピー

**Client API キー（`ptlc_` で始まる）**

1. 同じ管理者アカウントのまま、右上のアカウントのアイコン → **API Credentials**
2. Description に `hatch` と入れ、Allowed IPs は空欄のまま **Create**
3. 表示されたキーをコピー

> Client API キーは必ず管理者のアカウントで作ってください。一般ユーザーのキーだと接続確認で失敗します。

### Cloudflare

**API トークン**

1. [Cloudflare の API トークンの画面](https://dash.cloudflare.com/profile/api-tokens) → **トークンを作成する**
2. テンプレートの **ゾーン DNS を編集する**（Edit zone DNS）→ **テンプレートを使用**
3. 権限に **ゾーン → ゾーン → 読み取り** を追加する（DNS → 編集 は最初から入っている）
4. ゾーンリソースで、ゲームサーバーに使うドメイン（例 `example.com`）を選ぶ
5. **概要に進む** → **トークンを作成** → 表示された値をコピー

ゾーン ID は初期設定では不要です。初期設定の後、管理画面の「ドメイン」で登録するときに使います（Cloudflare でドメインを開いた「概要」ページの右下にあります）。

### Uptime Kuma

| 項目 | 入れる値 |
|---|---|
| URL | Uptime Kuma を開くときのアドレス（ポート番号も含む）。Tailscale 経由なら `http://kuma:3001` など |
| ユーザー名・パスワード | Uptime Kuma にログインするときのもの。Hatch が監視を登録するときに使います |
| API キー | **設定 → API キー → API キーを追加**。名前は `hatch`、有効期限は「無期限」。表示されたキー（`uk` で始まる）をコピー |

### Discord

画面の順番どおりに進めれば、サーバー・ロール・チャンネルの ID を手でコピーする必要はありません。

**1. アプリを作る**

1. [Discord Developer Portal](https://discord.com/developers/applications) → 右上の **New Application**
2. 名前（例 `Hatch`）を入れ、規約に同意して **Create**

**2. クライアントID とシークレット**

1. 左のメニューの **OAuth2**
2. **Client ID** の **Copy** → 画面の「クライアントID」に貼り付け
3. **Client Secret** の **Reset Secret** → 表示された値を「クライアントシークレット」に貼り付け
4. 同じ画面の **Redirects** → **Add Redirect** に、初期設定画面に表示される URL（`<公開 URL>/api/auth/callback`）を入れて **Save Changes**

**3. Bot のトークン**

1. 左のメニューの **Bot** → **Reset Token** → 表示された値を「Bot のトークン」に貼り付け
2. 同じ画面の **Privileged Gateway Intents** で **Server Members Intent** をオン → **Save Changes**

**4. Bot を Discord サーバーに招待**

1. 初期設定画面で **接続確認** を押す
2. 「Bot をサーバーに招待」ボタンが出たら押し、Hatch で使う Discord サーバーを選んで **認証**（サーバーの管理権限が必要）
3. もう一度 **接続確認** を押し、Discord サーバーを選ぶ

招待のリンクには、Bot に必要な権限（チャンネルを見る・メッセージを送る・埋め込みリンク・メッセージ履歴を読む）があらかじめ入っています。

**5. ロールとチャンネル**

Discord のロールごとに、Hatch での権限を選びます。権限は3段階です。

| 権限 | できること |
|---|---|
| 管理者 | すべての操作と設定 |
| サポーター | 管理者が割り当てたサーバーの閲覧と、起動・停止・再起動。自分のサーバーも作れます |
| 利用者 | 自分のサーバーを作って使えます |

画面には Discord のロールが並び、それぞれ右側で「管理者・サポーター・利用者・使わない」から選びます。ロールの下には、そのロールを持っている人数が出ます。

- **管理者にするロールは1つ以上必須** です。自分が持っているロールを選んでください。誰も持っていないロールを選ぶと警告が出ます。
- **Discord サーバーのオーナーは、ロールが無くても管理者としてログインできます。** ロールを付け忘れても締め出されません。
- 複数のロールを持つ人は、いちばん強い権限になります。
- 選んだロールごとに、1人が作れるサーバーの台数を決めます。
- お知らせ・管理者向けのチャンネル（任意）は、Bot が通知を送る先です。Bot がそのチャンネルに書き込めるようにしておきます。

ロールがまだ無い場合は、Discord のサーバー名 → **サーバー設定 → ロール → ロールを作成** で作り、自分に管理者用のロールを付けてから、画面の **一覧を更新** を押します。

> 人数が表示されないときは、Developer Portal の **Bot → Server Members Intent** がオフです。オンにして **一覧を更新** を押してください。

サポーターに受け持つサーバーを割り当てるのは、初期設定の後に管理者が行います（API：`PUT /api/servers/{サーバー}/supporters/{ユーザーID}`）。

## 初期設定の後

1. 完了画面の **Discord でログイン** を押す
2. 二段階認証は任意です。使う場合は、ログイン後に「設定 → 二段階認証」からオンにします（Google Authenticator などの認証アプリを使います）
3. 管理画面で次の順に登録します
   - **ドメイン**：ゲームサーバーに使うドメインと Cloudflare のゾーン ID
   - **IP と紐付け**：edge サーバーの IP を確認
   - **アドレス枠**：ポートの範囲とホスト名の形を作り、「DNS を作成」
4. **管理 → ノードと edge** で、プレイヤーの入口（edge）を登録します
   - **Linode のアカウント**：Cloud Manager 右上のアカウント → API Tokens → Create a Personal Access Token。Linodes は Read Only、Firewalls は Read/Write、他は No Access にして作り、表示されたトークンを貼り付けます（契約が複数あれば、契約ごとに追加）
   - **ファイアウォール**：Cloud Manager の Firewalls → Create Firewall で作り、SSH など必要なルールだけを入れておきます。ここで登録すると、ゲームのポートは Hatch が自動で開け閉めします（サーバーを作ると開き、完全に削除すると締まる）
   - **edge**：edge/install-edge.sh で入力した名前で登録し、Linode とファイアウォールを選びます。複数の edge で1つのファイアウォールを共有しても、edge ごとに別にしても構いません

## 困ったとき

| 症状 | 対処 |
|---|---|
| 初期設定コードが分からない | コンテナの中で `hatch-setup` を実行すると表示されます |
| 接続確認で「接続できません」 | このコンテナからそのサービスへ通信できるか（Tailscale・ファイアウォール・URL のポート番号）を確認 |
| 「DNS を作成できませんでした」「10000: Authentication error」「DNS を編集する権限がありません」 | Cloudflare の API トークンに、そのドメインの DNS を編集する権限がありません。Cloudflare の **プロフィール → API トークン** で該当トークンの **編集** を開き、権限に「ゾーン → DNS → 編集」と「ゾーン → ゾーン → 読み取り」があること、**ゾーンリソース** にそのドメインが入っていること（「すべてのゾーン」か、そのドメインを指定）を確認して保存します。トークンの値は変わらないので、Hatch 側の入れ直しは不要です。直したら、アドレス枠の画面でもう一度「DNS を作成」を押します。トークンを作り直した場合は、コンテナで `hatch-setup --reset` を実行して新しいトークンを入れます |
| 「edge.<ドメイン> の DNS を反映できませんでした」「使用中の edge が登録されていません」 | edge（プレイヤーの入口）をまだ登録していません。**管理 → ノードと edge → edge を登録** で登録すると、edge.<ドメイン> の A レコードが自動で作り直されます（Linode を使わない edge は「Linode 以外」を選ぶ）。後から直したいときは、**管理 → IP と紐付け** の各行の「…」→ **DNS を反映し直す** |
| 保存後、「再起動しなかった」と表示される | コンテナの中で `systemctl restart hatch.target` を実行してからログイン |
| ログインで「Hatch を使えるロールが、あなたの Discord アカウントに付いていません」 | Discord で自分に、初期設定で管理者（またはサポーター・利用者）にしたロールが付いているか確認。付いていなければ付けてから再ログイン。Discord サーバーのオーナーなら、ロールが無くても管理者としてログインできます |
| ログインで「Invalid OAuth2 redirect_uri」 | Developer Portal の Redirects に、初期設定画面に表示された URL と完全に同じものを登録 |
| 公開 URL を変えたい・設定をやり直したい | コンテナの中で `hatch-setup --reset` を実行し、表示されたコードで初期設定画面を開き直す（今の値は残るので、変える項目だけ入力） |
| 管理者がログインできなくなった | 同上（`hatch-setup --reset` で管理者のロールを選び直せます） |

### 設定の保存先

| ファイル | 内容 |
|---|---|
| `/etc/hatch/hatch.env` | インストール時に自動で作る値（DB の接続先・秘密鍵など）。通常は編集不要 |
| `/var/lib/hatch/setup.env` | 初期設定画面で保存した値。`hatch.env` より優先されます |

どちらも root と hatch ユーザーしか読めません。リポジトリや他の場所にはコピーしないでください。
