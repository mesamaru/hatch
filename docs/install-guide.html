Hatch インストール詳細ガイド

Proxmox でのスクリプト実行から、オーケストレーターが正式に動作するまでの完全なステップバイステップガイドです。
各手順で入力する値、確認すべき出力、トラブルシューティングをまとめています。

0事前確認

インストール前に、以下の環境が整っていることを確認してください。

  • Proxmox VE 8 以降が動作していること

    Proxmox ホストで pveversion を実行して確認。出力例：pve-manager/8.2.2/...

  • root ユーザーでアクセス可能なこと

    インストーラーは root 権限が必要です。

  • ネットワークが接続されていること

    Debian テンプレートをダウンロードし、インターネットにアクセスする必要があります。

  • ストレージが十分にあること

    最小 10GB のディスク空き容量が必要。デフォルトではコンテナに 10GB を割り当てます。

  • Tailscale の認証キーを用意すること（オプション）

    Tailscale に自動接続したい場合のみ。後からでも設定可能。

1Proxmox ホストでコンテナ作成スクリプト実行

Proxmox VE ホストのシェルで以下を実行します。対話形式で設定値を入力していきます。

コマンド実行

bash -c "$(curl -fsSL https://raw.githubusercontent.com/mesamaru/hatch/main/ct/hatch.sh)"

期待される出力

   hatch ─ Pterodactyl 自動デプロイ基盤のインストール

 … テンプレートを確認しています
 ✓ テンプレート: debian-13-standard_13.1_amd64.tar.zst
 … コンテナ XXX を作成しています
 ✓ コンテナ XXX を作成しました
 … コンテナを起動しています
 ✓ ネットワークに接続しました
 … インストールしています（数分かかります）
 ✓ インストールが完了しました

✓Hatch の準備ができました。

   パネル  http://192.168.1.50:8080
   初期設定 pct enter 100 → hatch-setup
   更新    pct enter 100 → update
   Tailscale を後から接続する場合: pct enter 100 → tailscale up
このメッセージに表示されたコンテナ ID（この例では 100）をメモしておいてください。次のステップで使います。

対話形式での設定

スクリプト実行時に、以下の画面が表示されます（非対話実行の場合はスキップ）：

設定方法を選んでください
  1) 標準設定（CPU 2 / メモリ 2048MB / ディスク 10GB / DHCP）
  2) 詳細設定

標準設定の場合

1 を選択すれば完了。デフォルト値でコンテナが作成されます。

詳細設定の場合

2 を選択すると、以下の項目を対話形式で入力できます：

  • コンテナID一意の番号（例：100）。通常は自動で割り当てられた値で OK
  • ホスト名コンテナの識別名。デフォルト：hatch
  • CPUコア数割り当てるコア数。デフォルト：2
  • メモリ (MB)割り当てるメモリ。デフォルト：2048（2GB）
  • ディスク (GB)割り当てるディスク。デフォルト：10（最小推奨）
  • コンテナのストレージ保存先ストレージ。通常は最初の選択肢で OK
  • ネットワークブリッジブリッジ名。デフォルト：vmbr0
  • IPアドレスdhcp または 192.168.1.50/24 の形式
  • ゲートウェイ固定 IP を選択した場合のみ必須。例：192.168.1.1
  • VLAN タグ不要な場合は空欄。VLAN を使う場合は番号を入力
  • Tailscale 認証キーTailscale に自動接続する場合のみ入力。後からでも OK
固定 IP を選択した場合は、ゲートウェイの入力が必須です。

2コンテナにアクセス

コンテナ作成後、シェルにアクセスして初期設定を進めます。

コンテナシェルへのアクセス

ステップ 1 で表示されたコンテナ ID を使用します（この例では 100）：

pct enter 100

実行すると、コンテナ内の root シェルにアクセスできます（プロンプトが root@hatch:~# に変わります）。

コンソール自動ログイン設定により、パスワード入力は不要です。

コンテナ内での確認

コンテナ内で以下のコマンドを実行して、インストール状況を確認できます：

root@hatch:~# ls -la /opt/hatch/
root@hatch:~# systemctl status hatch.target
root@hatch:~# journalctl -u hatch-api -n 20

もし入れない場合

SSH でアクセスしたい場合は、コンテナ内で root パスワードを設定：

root@hatch:~# passwd root

その後、Proxmox ホストで pct exec 100 -- hostname -I でコンテナの IP を確認し、SSH でアクセス可能になります。

3hatch-setup で初期設定

コンテナ内で hatch-setup コマンドを実行し、外部サービスと連携する設定をします。
入力値は その場で接続確認 されるため、誤った設定では先に進めません。

コマンド実行

hatch-setup

設定項目と入力値

以下の順で対話形式で設定値を入力します。各項目で接続確認が行われます。

① ホスト名・タイムゾーン

Hatch ホスト名（Tailscale 内での識別名、デフォルト: hatch）:

デフォルト値（hatch）で OK。Tailscale 内から http://hatch:8080 でアクセスできます。

タイムゾーン（デフォルト: Asia/Tokyo）:

日本の場合は Asia/Tokyo で OK。

② Tailscale 内での URL

Tailscale 内から見たこのコンテナの URL（例 http://hatch:8080）:

ホスト名が hatch の場合は http://hatch:8080 を入力。
ポート 8080 は固定。ホスト名は①で入力した名前に合わせてください。

③ Pterodactyl パネル

Pterodactyl パネルのホスト名または URL（例 panel.example.com）:

パネルが https://panel.example.com で動作している場合、panel.example.com を入力。
または完全な URL https://panel.example.com でも OK。

Pterodactyl Application API キー:

パネルの Admin Panel → API Management → Applications → Application Tokens から作成。
以下の権限が必要：user:read, user:update, node:read, allocation:read, allocation:create, server:read, server:create, nest:read, egg:read

Pterodactyl root 管理者の Client API キー:

root 管理者アカウントの Account → API Tokens から作成。

API キーは秘密情報です。ログファイルやバージョン管理に出さないよう注意してください。

④ Cloudflare

Cloudflare API トークン（Zone:Read・DNS:Edit の権限が必要）:

Cloudflare の API Tokens → Create Token から、Template: Edit zone DNS で作成。
権限：Zone:Read、DNS:Edit

Cloudflare ゾーン ID（例 abcdef1234567890）:

Cloudflare の Zone Details ページ右下に表示されます。ここでは一度確認するだけ。
画面の「管理 → ドメイン」から後で登録します。

⑤ Uptime Kuma

Uptime Kuma のホスト名または URL（例 http://kuma.example.com:3001）:

Uptime Kuma が http://192.168.1.60:3001 で動作している場合、http://192.168.1.60:3001 を入力。
Tailscale に参加している場合は http://kuma:3001 でも OK。

設定完了後

hatch-setup が全ての接続を検証し、以下を実行します：

  • 設定ファイル /etc/hatch/hatch.env を作成
  • API サーバーを起動

完了すると ✓ セットアップが完了しました と表示されます。

コンテナから抜ける場合は exit を入力します。

4Web パネルへのアクセス確認

API が正常に起動したことを確認します。

ステップ 1 で表示された URL にアクセス

例：http://192.168.1.50:8080
ブラウザで開くと、Hatch パネルが表示されます。

注意 Tailscale 外からは、IP アドレスと 8080 ポートでアクセスしてください。
ホスト名（http://hatch:8080）でアクセスできるのは Tailscale に参加したマシンだけです。

もし表示されない場合

コンテナ内で以下を確認：

root@hatch:~# journalctl -u hatch-api -n 50
root@hatch:~# systemctl status hatch.target
root@hatch:~# ss -tlnp | grep 8080
ポート 8080 が別のプロセスで使われていないか、ファイアウォールで遮断されていないか確認してください。

5Web パネルの公開設定

利用者がアクセスできるように、Web パネルをインターネットに公開します。2つ方法があります。

方法 A：Cloudflare Tunnel（推奨）

コンテナ内で cloudflared をセットアップ。受信ポート不要で最も簡単。

root@hatch:~# apt-get install cloudflared
root@hatch:~# cloudflared tunnel login

その後、Cloudflare ダッシュボードで Tunnel を作成し、https://<パネルのドメイン> → localhost:8080 にルーティング設定。

方法 B：edge サーバーの nginx 中継

edge サーバーの nginx から Tailscale 経由で Hatch に接続。
詳細は README の「edge サーバーのセットアップ」 を参照。

どちらの方法でも、https://<パネルのドメイン>/ で アクセス可能にしてください。

6画面からの初期設定

Web パネルにアクセスし、Discord でログインして初期設定を進めます。

ログイン

https://<パネルのドメイン>/ を開き、「Discord でログイン」ボタンをクリック。
初回ログインのユーザーは自動作成されます。管理者は別途設定が必要です。

ドメイン登録（管理画面）

管理 → ドメイン → 追加

  • ドメイン例：nuids.jp
  • Cloudflare ゾーン IDhatch-setup で入力した値

登録すると、edge.nuids.jp が自動で作成されます。

IP と紐付け（管理画面）

管理 → IP と紐付け → 追加

edge サーバーの IP アドレスを登録。複数台の edge サーバーがある場合は、それぞれ登録。

アドレス枠作成（管理画面）

管理 → アドレス枠 → 追加

  • ポート範囲例：25560-25569
  • ホスト名パターン例：mc{nn}trt（{nn} は自動で 01 から 99 に置換）
  • 対象外ポート例：25560（予約済みなど。複数指定可）

保存後、「DNS を作成」ボタンで DNS レコードが自動作成されます。
完成後は mc01trt.nuids.jp のようなアドレスが利用者に提供されます。

Discord ロール連携（管理画面）

管理 → Discord ロール連携 → 追加

Discord のロール ID と、そのロールが持つ権限（サーバー作成可能台数など）を対応付け。

管理 → 利用規約 → 編集

利用者に表示する利用規約を登録。登録後は全利用者が同意を求められます。

8トラブルシューティング

うまくいかない場合の確認方法をまとめています。

コンテナに入れない

症状： pct enter 100 が動作しない
確認： Proxmox で pct list を実行し、コンテナが起動しているか確認。ステータスが running でなければ pct start 100 で起動。

API が起動しない

症状： ブラウザで http://IP:8080 に接続できない
確認： 
root@hatch:~# systemctl status hatch-api
root@hatch:~# journalctl -u hatch-api -n 100 | tail -30
エラーが見つかれば、メッセージに従って対応。多くの場合は hatch-setup の設定値の誤りです。

Pterodactyl パネルに接続できない

症状： 管理画面でパネルの設定確認に失敗
確認： 
root@hatch:~# curl -s https://panel.example.com/api/client -H "Authorization: Bearer API_KEY" | jq
API キーが正しいか、権限が不足していないか確認。

Cloudflare DNS が作られない

症状： アドレス枠を作成しても DNS に登録されない
確認： Cloudflare API トークンの権限を確認。Zone:Read と DNS:Edit が両方あるか。 
root@hatch:~# journalctl -u hatch-api | grep -i cloudflare

Discord ログインが失敗

症状： 「Discord でログイン」をクリックしてもエラーになる
確認： Discord Developer Portal で OAuth2 の「リダイレクト URI」が正しく設定されているか。
入力値：https://<パネルのドメイン>/api/auth/callback

Uptime Kuma に接続できない

症状： hatch-setup で Kuma の接続確認に失敗
確認： Kuma が起動しているか、URL が正しいか。IP アドレス確認： 
root@hatch:~# curl http://192.168.1.60:3001/

それでも解決しない場合

コンテナ内の詳細ログを確認：

root@hatch:~# journalctl -u hatch.target -n 200
root@hatch:~# cat /etc/hatch/hatch.env  # ※ 秘密情報が含まれているため取り扱い注意

GitHub Issues で報告する場合は、上記ログの 秘密情報（API キーなど）を削除 した部分をご共有ください。

✓セットアップ完了

これで Hatch の基本的なセットアップが完了しました。

次のステップ

  • テスト環境の整備： 本番前に、同じ Proxmox にテスト用のコンテナ（PD_INSTANCE=stg）を作成し、一通りの機能をテスト。
  • バックアップ戦略： PostgreSQL データベースと Object Storage の定期バックアップを設定。
  • 監視設定： Uptime Kuma で重要な機能の監視を追加し、アラートが Discord に通知されるか確認。
  • ドキュメント整備： 利用者向けの利用規約・プライバシーポリシーを完成させる。

詳細な設定・仕様は docs/ENVIRONMENT.md、docs/SPEC.md、README を参照。
