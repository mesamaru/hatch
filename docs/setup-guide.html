Hatch 構築ガイド

Discord と Web パネルからゲームサーバーを一回の指示で作成・公開・監視・運用するための基盤「Hatch」を、
ゼロから動かすまでの手順をまとめています。まずはテスト環境で一通り試してから本番を作ってください。

目次 全体の流れ 1. 必要なもの 2. 外部サービスの準備 3. インストール 4. edge サーバー 5. Web パネルの公開 6. 画面からの初期設定 7. 動作確認 8. 更新・運用 困ったとき

i全体の流れ

Hatch は次の部品で構成されています。まず土台（Proxmox・Tailscale・Cloudflare など）を用意し、 オーケストレーター本体（このリポジトリ）を1つの LXC コンテナにインストールする、という順番で進めます。

プレイヤー ─► edge サーバー（Linode 等）── Tailscale ──┐
                                                        │
利用者 ─► panel.example.jp ─► オーケストレーター（Proxmox の LXC = Hatch 本体）
                               │  PostgreSQL・API・worker・Bot
                               ├─► Pterodactyl パネル ─► Wings ノード
                               ├─► Uptime Kuma（監視。別の場所に設置）
                               ├─► Object Storage（バックアップ）
                               └─► Discord（Bot・ログイン・通知）
現在は開発の初期段階です。インストーラー・更新の仕組み・DB スキーマ・edge エージェント・画面のデモは動きますが、 サーバー作成の中心処理は今後のリリースで追加されます（update 一発で反映されます）。詳しくはリポジトリの docs/SPEC.md を参照してください。

1必要なもの

下のチェックを付けながら準備すると進捗が分かりやすくなります（ブラウザに保存されるだけで、送信はされません）。

メール不要 通知とパスワード再設定は Discord の DM で行うため、メールサーバーは不要です。

2外部サービスの準備

詳細な設定値は docs/ENVIRONMENT.md にまとめてあります。ここでは順番だけ示します。

  1. Cloudflare：ドメインのネームサーバーを移し、DNS 編集権限だけの API トークンを作成
  2. Tailscale：tag:hatch・tag:edge・tag:wings・tag:kuma のタグと ACL、LXC・edge 用の認証キーを用意
  3. Uptime Kuma：オーケストレーターとは別の場所に立て、連携用ユーザー・API キー・自己監視通知用の Discord Webhook を用意
  4. Object Storage：バケットとアクセスキーを作成し、パネルのバックアップ先を S3 に設定
  5. Discord：Developer Portal でアプリを作成（Bot トークン、クライアント ID・シークレット、OAuth コールバック https://<パネルのドメイン>/api/auth/callback、Server Members Intent を有効化）。お知らせ・運営通知用のチャンネルとロールも用意
  6. GitHub：このリポジトリを自分のアカウントに fork または新規作成し、git tag v0.1.0 && git push --tags で最初のリリースを作る（Actions が配布ファイルを作成）

Tailscale ACL の例

{
  "tagOwners": {
    "tag:hatch": ["autogroup:admin"], "tag:edge": ["autogroup:admin"],
    "tag:wings": ["autogroup:admin"], "tag:kuma": ["autogroup:admin"], "tag:panel": ["autogroup:admin"]
  },
  "acls": [
    {"action": "accept", "src": ["tag:edge"], "dst": ["tag:wings:25560-25569,30000-30999"]},
    {"action": "accept", "src": ["tag:edge"], "dst": ["tag:hatch:8080"]},
    {"action": "accept", "src": ["tag:hatch"], "dst": ["tag:panel:443", "tag:kuma:3001"]},
    {"action": "accept", "src": ["tag:kuma"], "dst": ["tag:hatch:8080", "tag:edge:*"]},
    {"action": "accept", "src": ["tag:panel"], "dst": ["tag:wings:8080,2022"]},
    {"action": "accept", "src": ["autogroup:admin"], "dst": ["*:*"]}
  ]
}

ポート範囲は、実際に作るアドレス枠（例：25560〜25569）に合わせて変更してください。

3オーケストレーターのインストール

Proxmox VE ホストのシェルで実行します。Debian 13 のテンプレートは自動で取得されます。

bash -c "$(curl -fsSL https://raw.githubusercontent.com/mesamaru/hatch/main/ct/hatch.sh)"

完了したら、コンテナに入って初期設定をします。入力した値はその場で接続確認されます。

pct enter <コンテナ ID>
hatch-setup

非対話でインストールする場合

PD_YES=1 var_cpu=2 var_ram=2048 var_disk=10 \
  var_net=192.168.1.50/24 var_gateway=192.168.1.1 \
  var_ts_authkey=tskey-auth-xxxx \
  bash -c "$(curl -fsSL https://raw.githubusercontent.com/mesamaru/hatch/main/ct/hatch.sh)"
変数既定値内容
var_hostnamehatchホスト名
var_cpu / var_ram / var_disk2 / 2048 / 10コア数 / MB / GB
var_net / var_gatewaydhcp固定 IP は 192.168.1.50/24 の形式
var_ts_authkeyなしTailscale 認証キー
PD_CHANNELstablebeta でベータ版を使う
テスト環境を作る場合は、同じ Proxmox にもう1つ LXC を作り、hatch-setup の中で PD_INSTANCE=stg を指定してください。本番とレコード・監視が混ざりません。

4edge サーバーのセットアップ

プレイヤーが接続する入口です。Linode などの Debian / Ubuntu サーバーで root 実行します。

bash -c "$(curl -fsSL https://raw.githubusercontent.com/mesamaru/hatch/main/edge/install-edge.sh)"

edge エージェントはオーケストレーターから HAProxy 設定を取りに行き、検証してから適用します。 オーケストレーターが止まっていても最後に取得した設定で動き続けます。

自分のアカウントに fork して使う場合は、両方のコマンドの前に PD_REPO=あなたのユーザー名/hatch を付けてください。
Linode のファイアウォールでは、アドレス枠のポート範囲（TCP・UDP）と 80/443 だけを開放してください。

5Web パネルの公開

オーケストレーターの API を直接インターネットに公開しないでください。どちらかの方法で Web パネルだけを公開します。

方法内容
おすすめCloudflare Tunnel（LXC に cloudflared を入れる。受信ポートを開けなくてよい）

6画面からの初期設定

ここまで終わったら、ブラウザで https://<パネルのドメイン>/ を開き、Discord でログインします。

  1. 管理 → ドメインで使用するドメインを登録（Cloudflare のゾーン ID を入力すると edge.<ドメイン> が自動で作られます）
  2. 管理 → IP と紐付けで edge サーバーの IP を確認
  3. 管理 → アドレス枠で、例えば「25560–25569 / mc{nn}trt / 対象外 25560」を作成し、「DNS を作成」を押す
  4. 管理 → Discord ロール連携でロールと権限・上限台数の対応を登録
  5. 管理 → 利用規約を登録（同意していない利用者には同意シートが出ます）

これで利用者は作成画面で mc01trt.nuids.jp のようなアドレスを選ぶだけになります。

8更新・運用

コンテナ内で次のコマンドが使えます。更新前に DB を自動で退避し、起動を確認できなければ自動で前のバージョンに戻ります。

update                 # 最新の安定版へ
update --check         # 更新があるか確認だけ
update --channel beta  # ベータ版を含めて最新へ
update --rollback      # 1つ前に戻す（--restore-db で DB も戻す）

?困ったとき

症状確認するところ
コンテナ内で API が起動しないjournalctl -u hatch-api -n 80、hatch-setup を再実行して設定漏れを確認
edge に反映されないedge サーバーで journalctl -u hatch-edge -f、オーケストレーターとの Tailscale 疎通
DNS が作られないCloudflare トークンの権限（Zone:Read・DNS:Edit）とゾーン ID の一致
ログインできないDiscord アプリの OAuth コールバック URL と Server Members Intent
